# Plan: Runner & Reference Adapter (Go SQL Benchmark, Phase 2)

## Summary
Build the measurement pipeline on one baseline library: an `Adapter` interface (one method per scenario), a custom runner that executes six scenarios under a low-traffic and a stress profile and records p50/p95/p99, throughput, B/op, allocs/op, CPU time and error rate, a validated JSON result format, and the `database/sql` (pgx/stdlib) reference adapter. A `benchcmp` tool turns the "two runs agree within ~10% p95" success signal into an executable check.

## User Story
As a Go backend engineer building the benchmark, I want a runner that measures one library end to end into JSON, so that Phase 3 adapters and the Phase 4 report generator only plug into a proven pipeline.

## Problem → Solution
Seeded Postgres 15 and no benchmark code → `make bench` runs `database/sql` through 6 scenarios x 2 profiles x N repeats, writes `results/run-<ts>.json` that passes schema validation, and `benchcmp` shows two runs' p95 within tolerance.

### ERROR_HANDLING
// SOURCE: internal/seedcheck/seedcheck.go:46-54
```go

Wrap with a package prefix and `%w`: `fmt.Errorf("runner: reseed: %w", err)`. Never swallow; the only intentional drop is an op error caused by window-end cancellation (see Task 5).

### MAIN_PATTERN / LOGGING_PATTERN
// SOURCE: cmd/dbcheck/main.go:20-43
```go
func main() {
	if err := run(dsn); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(exitCheckError)
	}
	fmt.Println("seed OK: ...")
}
func run(dsn string) error { /* defer db.Close() */ }
```
`main` calls `os.Exit` once; all work is in `run() error` so defers run. Results to stdout, errors to stderr, no logging library. Progress lines go to stderr.

### DRIVER_USAGE
// SOURCE: upstream bench/raw.go:44-52 (adapted)
```go

```

### REFERENCE_SQL
// SOURCE: upstream bench/raw.go:10-17
```go
rawInsertSQL = `INSERT INTO models (name, title, fax, web, age, "right", counter) VALUES ($1, $2, $3, $4, $5, $6, $7)`

```

## Design Decisions (made in this plan; flagged because the PRD left them open)

| Decision | Choice | Alternative | Why |
|---|---|---|---|
| Scenario methods return | `(rows int, err error)`; runner checks `rows == expected` and counts a mismatch as an error | return full values | Cheap built-in correctness; value-level cross-adapter check stays Phase 3. Adapter contract: must scan every selected column into Go values |
| Unsupported scenario | adapter returns `bench.ErrUnsupported`; runner probes once, then records the cell as `na` | capability flags | One mechanism, no extra interface surface |
| State between cells | `TRUNCATE ... RESTART IDENTITY` + reseed from embedded `db/seed.sql` before every cell, fresh adapter (fresh pool) per cell | reseed per run | Removes carry-over (table growth, bloat, warm pool); costs about 1 s per cell |
| DELETE | harness bulk-inserts a pool of ids (untimed, before warm-up); workers take the next id atomically; the window ends early if the pool is exhausted | per-op untimed insert | Keeps throughput = timed ops / wall clock with no setup inside the window |
| UPDATE / SELECT | random id in `1..seeded models` (10000), per-worker deterministic PCG | fixed id | Avoids a single hot row; upstream used a constant |
| JOIN | all `orders` of one customer joined to `customers` (`customer_id` in `1..1000`), expect 10 rows | full-table join | Indexed, realistic, result size fixed by the seed |
| UNION | `customers` and `suppliers` rows for one city (`'city 0'..'city 49'`), expect 40 rows (20 + 20) | full UNION | Same shape, bounded result |
| Latency | service time of one call (start to return), recorded for successful ops only; exact percentiles by sorting all samples (nearest-rank) | HdrHistogram | No dependency; sample counts stay in the low hundreds of thousands |
| Low profile pacing | 4 workers, one op every 10 ms per worker (start-to-start), 1 s warm-up, 5 s window | open-loop scheduler | Simple. Not coordinated-omission-corrected: acceptable because load is far below saturation |
| Stress profile | 100 workers, no pacing, 2 s warm-up, 10 s window, pool size = workers | other counts | PRD default; Phase 5 resolves stress parameters. All values are flags |
| Pool | `MaxOpenConns = MaxIdleConns = workers`, unlimited lifetime | tuning sweeps | PRD: one fixed documented pool; matches `max_connections=300` from Phase 1 |
| CPU | process `getrusage` delta (user+sys) over the window / ops | pprof | PRD decision. Includes GC and harness cost, stated in the output docs |
| Repeats | default 3; per-cell median of each metric; all repeats kept in JSON | single run | PRD hygiene |
| Order | library order shuffled per repeat from a recorded seed | fixed order | PRD hygiene. With one library it only exercises the code; Phase 3 benefits |

### Task 2: Pure statistics
- **ACTION**: Tests first, then `internal/runner/stats.go`.
- **IMPLEMENT**:
  ```go
  // percentile returns the nearest-rank percentile (p in 0..100) of a sorted slice; 0 for empty input.
  func percentile(sorted []int64, p float64) int64
  // median returns the median of values; 0 for empty input.
  func median(values []float64) float64
  // summarize builds Metrics from samples (successful-op latencies, unsorted), counters and window deltas.
  func summarize(in windowStats) result.Metrics
  ```
  `windowStats{Latencies []int64; Errors int64; Elapsed time.Duration; AllocBytes, Mallocs uint64; CPU time.Duration}`. Rules: `ops = len(Latencies)`; `ErrorRate = errors / (ops + errors)` (0 when both 0); `ThroughputOpsPerSec = ops / Elapsed.Seconds()`; per-op fields divide by `ops` (0 when ops = 0, never NaN/Inf).
- **MIRROR**: TEST_STRUCTURE (table-driven AAA).
- **GOTCHA**: Nearest-rank index is `ceil(p/100 * n) - 1`, clamped to `[0, n-1]`. `summarize` must sort a copy or the caller's slice (document which). JSON cannot encode NaN/Inf, hence the zero guards.
- **VALIDATE**: Cases: empty, single sample, p50/p95/p99 of 1..100 (50, 95, 99), unsorted input, all errors (ErrorRate 1, ops 0, no NaN), zero elapsed.

### Task 4: Store (reseed and delete pool)
- **ACTION**: `internal/runner/store.go`.
- **IMPLEMENT**:
  ```go
  // Store prepares database state; Postgres implementation below, fakes in tests.
  type Store interface {
  	Reseed(ctx context.Context) error                        // db.Seed
  	InsertDeletable(ctx context.Context, n int) ([]int, error) // bulk insert, returns new ids
  }
  type pgStore struct{ db *sql.DB }
  func NewPGStore(db *sql.DB) Store
  ```
  `InsertDeletable`: `INSERT INTO models (...) SELECT <NewModel values> FROM generate_series(1, $1) RETURNING id`, scan ids into a pre-sized slice. `Reseed`: `db.ExecContext(ctx, bench seed)` — the multi-statement script runs through pgx's simple protocol only when there are no args; verify this works with `database/sql` + pgx (the plan's Phase 1 uses `psql`). If it does not, split the script on `;` statements or use `pgx.Conn.Exec` through `stdlib.OpenDBFromPool`/`Conn.Raw`; whichever is used, `seedcheck.Check` after the first reseed proves it.

### Task 5: Worker loop and cell execution (tests first, with fakes)
- **ACTION**: `internal/runner/{worker.go,cell.go}` driven by `runner_test.go` using a `fakeAdapter` (configurable per-scenario latency, error, wrong row count, `ErrUnsupported`) and `fakeStore`.
- **IMPLEMENT**:
  - `worker.go`: `runPhase(ctx, adapter, scenario, profile, seed, ids *deleteIDs, record bool) phaseResult` starts `profile.Workers` goroutines; each has `rand.New(rand.NewPCG(seed, uint64(workerID)))`, pre-allocated `latencies := make([]int64, 0, capacityHint)`, loops until the phase deadline. Pacing: `if p.Interval > 0 { next := start.Add(Interval); ...time.Sleep(until next) }`. Each op: build args by scenario (ids from RNG or the delete pool), `t0 := time.Now()`, call the adapter with a per-op timeout (`opTimeout = 10 * time.Second`), `d := time.Since(t0)`. Outcome rules: `err == nil && rows == expected` → record `d`; `errors.Is(err, bench.ErrUnsupported)` → abort the phase and return that sentinel; any other error or `rows != expected` → `errors++`, unless the phase deadline already passed and the error is `context.Canceled`/`DeadlineExceeded` (window-end artifact, dropped).
  - `cell.go`: `runCell(ctx, a bench.Adapter, s Store, sc bench.Scenario, p bench.Profile, dsn string, seed uint64) (result.Metrics, error)`:
    1. `s.Reseed` → `a.Init(pool)` (deferred `a.Close`).
    2. Probe: one call of the scenario; `ErrUnsupported` → return `errUnsupported` (caller records `na`). For DELETE the probe needs an id: insert 1 deletable first. Then `s.Reseed` again and re-`Init` is NOT needed (probe is a normal op); instead reseed lazily: do probe before the delete pool and accept the 1 row difference only for INSERT/DELETE, then reseed + re-init once if the probe mutated state (`Insert`, `Update`, `Delete`). Simplest correct rule: always probe, then close adapter, reseed, init again.
    3. For DELETE: `ids := s.InsertDeletable(p.DeletePool)`.
    4. Warm-up phase (`record=false`, `p.Warmup`).
    5. `runtime.GC()`, `runtime.ReadMemStats(&m0)`, `getrusage(&r0)`, `start := time.Now()`.
    6. Measure phase (`p.Duration`), then `elapsed := time.Since(start)`, `ReadMemStats(&m1)`, `getrusage(&r1)`.
    7. `summarize(windowStats{...})`.
  - `getrusage()`: wrapper returning `time.Duration` of `Utime+Stime`; on error return the error (do not ignore).
- **MIRROR**: ERROR_HANDLING, NAMING_CONVENTION (named constants: `opTimeout`, `capacityHint`).
- **GOTCHA**: (1) `time.Sleep` pacing drifts; use `time.Until(next)` and advance `next += Interval` to keep start-to-start spacing. (2) Do not call `ReadMemStats` inside the window. (3) The delete id index is `atomic.Int64`; once `>= len(ids)` the worker returns, and the window's `elapsed` is the real end time, not `p.Duration`. (4) `ErrorRate` must count wrong-row-count results, otherwise a broken adapter looks fast. (5) Latency slices are per worker and merged after the window, so recording takes no lock. (6) Keep allocations in the hot loop minimal (no `fmt`, no closures per op) because B/op includes harness allocations; document the floor via the fake adapter test (`B/op` of a no-op adapter must be tiny and constant).
- **VALIDATE** (`go test -race ./internal/runner/...`): fake adapter with 1 ms latency yields p50 about 1 ms; injected errors give the expected `ErrorRate`; wrong row count counts as error; `ErrUnsupported` yields `errUnsupported`; DELETE with a small pool ends early with `elapsed < Duration`; paced profile yields ops about `workers * duration / interval` (within 20%).

### Task 6: Matrix runner
- **ACTION**: `internal/runner/runner.go`.
- **IMPLEMENT**:
  ```go
  type Options struct {
  	DSN string; Adapters []func() bench.Adapter; Scenarios []bench.Scenario
  	Profiles []bench.Profile; Repeats int; Seed uint64; Progress io.Writer
  }
  func Run(ctx context.Context, store Store, opts Options, host result.Host) (result.Run, error)

After all repeats: build `Cell`s in stable order (library name, `AllScenarios` order, profile order); `Median` via per-field `median`; `na` cells carry `Reason: "n/a (unsupported)"`. - **MIRROR**: ERROR_HANDLING, MAIN_PATTERN (no logging lib).
- **GOTCHA**: An `na` cell is detected in repeat 1; skip the cell in later repeats instead of re-probing. A hard error (DB down, reseed failure) aborts the whole run with a wrapped error, it is not recorded as an `na`. Respect `ctx` cancellation between cells.
- **VALIDATE**: Test with two fake adapters (one unsupported for `union`): result has `ok` and `na` cells, `len(Repeats) == Repeats`, deterministic cell order, `Validate` passes, same seed gives the same shuffle order.

### Task 7: database/sql reference adapter
- **ACTION**: `internal/adapters/databasesql/databasesql.go` + integration test.
- **IMPLEMENT**: `type Adapter struct{ db *sql.DB }`, `New() bench.Adapter`, `Name() "database_sql"`. `Init`: `sql.Open("pgx", dsn)`, `SetMaxOpenConns/SetMaxIdleConns` from `PoolConfig`, `PingContext`. Methods (all with `ctx`, default driver exec mode, no explicit `Prepare`):
  - Insert: `ExecContext(insertSQL, ...)` → `RowsAffected()`
  - Update: `ExecContext(updateSQL, ..., id)` → `RowsAffected()`
  - Delete: `ExecContext("DELETE FROM models WHERE id = $1")` → `RowsAffected()`
  - Select: `QueryRowContext(selectSQL, id).Scan(all 8 columns)` → 1 (return `sql.ErrNoRows` wrapped as an error)
  - Join: `SELECT o.id, o.customer_id, o.status, o.total, o.created_at, c.name, c.email, c.city FROM orders o JOIN customers c ON c.id = o.customer_id WHERE c.id = $1`; `QueryContext`, scan every column of every row, `rows.Err()`, `rows.Close()`; return row count
  - Union: `SELECT name, email, city FROM customers WHERE city = $1 UNION SELECT name, email, city FROM suppliers WHERE city = $1`; same scan loop
  Wrap errors: `fmt.Errorf("databasesql: join: %w", err)`.
- **MIRROR**: REFERENCE_SQL, DRIVER_USAGE, ERROR_HANDLING.
- **IMPORTS**: `database/sql`, `context`, `fmt`, `_ "github.com/jackc/pgx/v5/stdlib"`, `internal/bench`.
- **GOTCHA**: `ReadSlice` in upstream preallocates `make([]Model, 100)`; here scan into a reused per-call local struct and count rows, to measure the library not the harness. Scan into `time.Time` for `created_at` (`TIMESTAMPTZ`). Always `defer rows.Close()` and check `rows.Err()`; leaking rows exhausts the pool and shows up as stress-profile timeouts.
- **VALIDATE** (integration, skips without DSN): on a seeded DB each method returns its expected count (1, 1, 1, 1, 10, 40); `Select` of a non-existing id returns an error.
